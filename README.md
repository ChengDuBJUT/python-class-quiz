# Python 编程基础与应用 · 题库练习站

**在线练习（不用下载）**：https://chengdubjut.github.io/python-class-quiz/

参照同学开源的 [mvstats-quiz](https://ledoo-bjut.github.io/mvstats-quiz) 做的静态题库站，纯 HTML/CSS/JS，无构建、无外链依赖、无后端。进度、收藏、错题只存在自己浏览器的 localStorage，不上传服务器。

## 打开方式

- **在线**：打开上面的 GitHub Pages 地址，手机 / 电脑浏览器都能用。
- **本地**：双击 `index.html` 即可。若浏览器对 `file://` 的本地存储有限制，可在目录内起个静态服务：

```bash
python3 -m http.server 8765
# 浏览器访问 http://127.0.0.1:8765/index.html
```

## 部署与更新（GitHub Pages）

仓库 `ChengDuBJUT/python-class-quiz` 的 `main` 分支根目录就是 Pages 源；`.nojekyll` 让 GitHub 跳过 Jekyll、原样发布静态文件。改完题目或样式后：

```bash
git add -A && git commit -m "更新题库" && git push
```

约 1 分钟内自动重新构建，同学刷新页面就能看到新内容，不需要重新打包分发。

> 仓库是 public（GitHub Pages 免费版要公开访问必须如此）。`robots.txt` 已设置不被搜索引擎收录；若希望被搜索到，删掉它即可。

## 功能

- 章节（1–12）、题型、考试范围三重筛选，随机顺序
- 收藏、错题本（客观题答错自动收录，答对自动移出；主观题可自评收录）
- **「不会 · 看答案」**：练习页不用作答，直接显示正确答案 / 参考程序与解析，该题自动记入错题本；掌握后可点「已掌握（移出错题）」移出。看答案按未掌握计入已答、不计入答对，进度条会标注「含看答案 N」，交卷清单里标为「看答案」以免与真正答错混淆
- **「问 DeepSeek」**：把**题目 + 你的答案 + 参考答案**一起打包，带在 `chat.deepseek.com/?q=…` 里打开新标签，官网会自动填进输入框，按一下 Enter 就发送。它不是让 AI 替你重做一遍，而是让它对照两个答案讲你错在哪、把哪个概念弄混了；答对了就讲这题背后的道理和最容易栽跟头的地方。还没作答时点它是另一种 prompt——只给思路、明确要求不给答案，不会提前泄题。同时复制到剪贴板兜底（未登录 / 被拦截时粘贴即可），内容过长会分级截断（我的答案 900→120→…、参考答案 1600→320→…）以保住自动填入；压到最短仍超 6000 字符的极少数长编程题会退回裸链接 + 剪贴板粘贴
- 抽题组卷：章节多选 + 题型 + 范围 + 题量 N + 按题型比例抽样
- 交卷小结：正确率、答错 / 看答案 / 未答清单、「只练错题」
- **简答题给答案 + 出处**：答案区保留换行排版，下方标「📖 出处：第 4 章 习题答案 简答(1)」，并用 `教材答案` / `据课件整理` 区分来源，方便回查课件原文
- **代码复习学习卡**：选中文件即在代码上方显示「🎯 这段考什么」，代码下方显示真实运行输出（含运行输入）、关键注释清单与易错点；第 4–8 章更新版文件带「更新版」角标
- **深色模式**：右上角 🌙 / ☀️ 一键切换。首次访问跟随系统 `prefers-color-scheme`，手动选过之后就按选择记住（localStorage）；`<head>` 里有一段极早执行的脚本先把 `data-theme` 打上，避免深色下先闪一帧白底；`color-scheme` 同步切换，所以下拉框、滚动条也是深色的
- 快捷键 `1`–`5` 选题、`Enter` 提交、`0` 不会看答案、`←`/`→` 翻题
- 进度、收藏、错题、知识点勾选全部存在浏览器 localStorage，不上传；只有你主动点「问 DeepSeek」时，当前题目才会被复制并带进你自己的 DeepSeek 会话

## 主题（深色模式）

`styles.css` 里没有任何写死的浅色值，全部走 `:root` 的语义变量，所以深色主题只是**一层变量覆盖**，规则本身一行没改：

```css
:root { --bg:#f6f1e8; --ink:#1f1a14; --surface:#fff; --accent:#1f5c4a; --accent-fill:#1f5c4a; --on-accent:#fff; ... }
:root[data-theme="dark"] { --bg:#12100d; --ink:#e9e3d7; --surface:#201c18; --accent:#63c3a3; --accent-fill:#2f6b57; --on-accent:#eef7f2; ... }
```

两点经验：

- **强调色拆成两个变量**。`--accent` 用于文字/图标/边框（深色下要更亮），`--accent-fill` 用于实心按钮和选中态（深色下反而要压暗）。只用一个变量的话，深色模式下按钮会亮得像霓虹灯。
- **代码高亮单独一组**（`--tok-kw` / `--tok-str` / `--tok-cmt` / `--tok-num`），浅色下的深蓝深红在深色底上几乎看不见，必须另配一套。

想再加一套主题（比如护眼米黄），照着写一个 `:root[data-theme="xxx"]` 块即可，切换逻辑不用改。

## 数据来源与勘误

1. 教材：`Python编程基础与应用习题及答案.docx`，共 14 章，按考试范围只取 **第 1–12 章**；第 13、14 章未入库。
2. **客观题答案以任课教师的 0429 勘误版 `1-12习题答案0429-勘误后.docx` 为准。** 该版只有 1–12 章、只有客观题答案，用红色（`FF0000`）标出改动处与批注。提取脚本 `tools/extract_answers_0429.py` 直接读 `word/document.xml`，按 run 记录颜色，输出 `tools/source/answers_0429.json`；`build_bank.py` 构建时以它覆盖原版答案。**11 道题被改正**：

| 题号 | 题型 | 原版 | 勘误版 |
| --- | --- | --- | --- |
| ch3 第 5 题 | 填空 | `j`（只写一个空） | `j / j`（两空都填 j） |
| ch4 第 4 题 | 填空 | `True` | `False`（链式比较） |
| ch2 第 4 题 | 选择 | `B`（序列印 B 并标红） | `A`（同页红字批注：包含了提前编译的解释执行） |
| ch7 第 4 题 | 选择 | `C` | `B` |
| ch8 第 4 题 | 选择 | `D` | `B` |
| ch9 第 1 题 | 选择 | `A` | `C` |
| ch9 第 3 题 | 选择 | `C` | `D` |
| ch12 第 3 题 | 选择 | `A` | `B` |
| ch7 第 1 题 | 判断 | 对 | 错 |
| ch8 第 1 题 | 判断 | 对 | 错 |
| ch8 第 5 题 | 判断 | 对 | 错 |

每道改动过的题都在解析里写明了「原版印什么、为什么改」。另有 ch5 第 3、4 题只被批注、答案未变：第 3 题选项 C、D 文字完全相同（教材注明 CD 均正确），第 4 题题干疑漏 `print(c)`。

3. **判断题答案有两种印法**：第 1、2、6、7、8、11、12 章用符号字体印成 `（1）-（5）√√×√√`，第 3、4、5、9、10 章写成 `对、对、对、对、错`。前者是 Wingdings 2 字符（`<w:sym char="F050"/F04F>`），经 docx→HTML 转换会整段丢失、看起来像"没印答案"，因此答案一律从 `word/document.xml` 直接提取，文本解析结果只做交叉校验。**60 道判断题答案全部来自原文，无人工补写。**
4. 0429 勘误版不含简答题与编程题。**简答题答案已单独补齐，见下一节**；编程题参考答案仍取自教材原书。
5. 少数编程题（如 ch6 第 8 题、ch12 第 7 题）教材未给参考程序，站点标注说明。
6. 教材第 2 章答案编号印刷错乱（`（1）（2）` 之后没有 `（3）(4)(5)`），解析脚本按「出现顺序」而非印刷编号与题号对齐；第 6 章选项里重复的字母标签已按位置规范化为 A/B/C/D。
7. 59 道代码自测题中全部用真实 Python 执行核验过输出（结果可在代码复习区对照实际 stdout）；仅 ch12 两道依赖 numpy/pandas、ch3 一道选项为文字描述，按库语义给定答案。

## 简答题标准答案（60/60 已补齐）

教材原书第 1、2、9–12 章简答题答案统一印「略」，只有第 3–8 章给了部分答案，且**答案编号与题号并不对应**（例如 ch3 答案区多出一条「数据类型」，ch8「三大特性」排在答案 (3) 而题目列表里是第 (5) 条）——按序号顺排会整体错位。

处理办法：

- **22 道**直接取自教材各章「习题答案」的简答部分，按**语义**逐条重新对齐题号（`tools/source/short_answers.json` 里 `origin: "official"`）。
- **38 道**教材印「略」，改由第 1–12 章课件 PDF 原文整理：`tools/locate.py` 把每道题干做 CJK 2/3-gram + 英文 token 打分，定位到最相关的课件页，取 top-3 页 + 邻域窗口（`tools/source/ppt_txt/chN.txt`，页级标记 `===== [chN pM] =====`）后撰写。
- 每道答案都带 `basis`（章 + 页码/习题答案编号），页面渲染为「📖 出处：…」，并打上 `教材答案` / `据课件整理` 标签，方便回查原文核对。
- 有两处如实标注了不确定：ch11 的 `sqlite3` 课件里只出现在标准库表格中（按标准用法作答并注明）；ch5「if/else 配对」课件未出现「就近配对」字样（按就近配对 + 缩进层级作答，并交叉引用嵌套 if 的例子）。

## 第 4–8 章代码：版本更新 + 三种考法

教师对第 4–8 章示例做过一次更新（`更新后的chapter/chapterN/chapterN/`）。`diff -rq` 逐文件比对后确认是**真实内容改动**（不是换行符/编码差异），站点已按新版本替换，旧版不再引用；被替换的文件名旁带「更新版」角标，章标题也会标「更新版」。第 1–3、9–12 章未改动，仍用原目录。

针对"代码可能以不同方式考察"，每个更新版文件都配了学习卡：

- **🎯 这段考什么**：一句话点出该文件的核心考点（放在代码上方，打开就能看到）
- **运行输出**：`tools/run_newcode.py` 真实执行（`PYTHONIOENCODING=utf-8` + 输入样本 + 超时保护）捕获的 stdout，需要交互的文件同时标出「运行输入」；故意演示异常的文件（如 ch6 不可哈希 list、ch8 `del` 后 NameError）把 traceback 单列并注明「多为故意演示」
- **关键注释**：3–6 条，按代码顺序讲清易被考到的机制（`and/or` 返回操作数、`is` vs `==`、生成器一次性、`nonlocal`、描述符与 MRO、`_Class__x` 名字改写、`__new__` 与 `__init__` 的分工等）
- **易错点**：该文件最容易写错/看错的一处

配套的 59 道代码自测题按三种考法命制（题干前缀直接标出考法）：

| 考法 | 数量 | 例子 |
| --- | ---: | --- |
| 【读结果】output | 28 | `day = "3"` 时某文件输出什么 |
| 【机制】concept | 11 | 为什么这里 `b is a` 为 True / `nonlocal` 不加会怎样 |
| 【找错】fix | 6 | 这段为什么会抛异常，改哪一行 |
| （早期 ch1–3、9–12 题） | 14 | 原有代码自测题，保留 |

三种考法的答案全部与真实执行结果对齐（`tools/quiz_extra.py` 里带 `expect_in` 断言，构建时校验 stdout 必须包含该片段，通过 `50/59`，其余为依赖第三方库或纯文字描述题）。

## 重建数据

站点本身开箱即用，**只有要重新解析原始资料时才需要**以下步骤；原始资料（`Python编程基础与应用习题及答案.docx`、`pythonProject-2025/chapter1..12`）不在本仓库，需要本地自备：

```bash
cd tools
python3 build_bank.py        # 依赖 tools/source/quiz_lines.txt（由 docx 导出）+ short_answers.json
python3 run_newcode.py       # 可选：重跑更新版代码，刷新 newcode_runs.json（真实输出）
python3 build_code_lab.py    # 依赖站点目录上一级的 pythonProject-2025/chapter1..12 与「更新后的chapter」
```

`locate.py` 用于新增简答题时回查课件原文：

```bash
python3 locate.py                              # 打印 60 道简答题各自的 top-3 相关页
python3 locate.py --dump ch5 12 --window 2     # 展开 ch5 第 12 页 ± 2 页原文
python3 locate.py --pages 1:48-52              # 直接读 1 号 PDF 的 48–52 页
```

`patch_app.py`、`notes_ch6.py`、`notes_ch7.py`、`notes_ch8.py`、`short_ch10.py`、`short_ch1112.py` 都是一次性辅助脚本：前四个用于把学习卡/简答题答案分批合并进 `source/*.json`（因为中文长文本直接写 heredoc 会被 shell 转义破坏），合完即止，重构时不必再跑。
